
# RFC: Workspace Metadata & Agent Export System

## Status

Proposed

## Summary

Introduce a workspace metadata generation system that allows Lea to expose repository structure, reasoning protocols, and AI-agent integration points in a deterministic and portable format.

Instead of generating agent-specific prompts directly, Lea will become the authoritative source of structural metadata for a repository. AI-specific files (Claude Code, OpenCode, Cursor, Codex, etc.) will be generated from this metadata layer.

This feature establishes Lea as the structural foundation of the PizenLabs ecosystem while keeping AI integrations lightweight and maintainable.

---

# Motivation

Currently, after running:

```bash
lea index .
```

Lea generates:

```text
.lea/
└── graph.db
```

While the graph database contains rich structural information, AI agents have no discoverable entry point that explains:

* What structural capabilities are available.
* How repository reasoning should be performed.
* Which workflow should be followed before reading source files.

As a result, most AI agents default to:

* Recursive file reading.
* Large-scale grep exploration.
* Excessive context accumulation.
* Architecture-unaware modifications.

This increases token usage and reduces reasoning quality.

Lea should provide a deterministic metadata layer that teaches agents how to navigate the repository structurally.

---

# Design Goals

## Primary Goals

* Make repository structure discoverable.
* Provide a consistent reasoning workflow.
* Reduce unnecessary code reading.
* Improve AI navigation quality.
* Keep Lea independent from any specific AI vendor.

## Non-Goals

* Prompt engineering.
* Vendor-specific system prompts.
* Embedding AI-specific logic into the graph engine.
* Replacing Lynx semantic discovery.

# Generated Files

## WORKSPACE.md

Location:

```text
.lea/WORKSPACE.md
```

Purpose:

Provide deterministic facts about the indexed repository.

Example:

```markdown
# Workspace Structural Metadata

Generated By: Lea
Version: 0.1.0

Repository Statistics

Languages:
- Go
- TypeScript

Nodes:
- 2,384

Edges:
- 11,204

Capabilities:
- Symbol Discovery
- Dependency Analysis
- Call Graph Traversal
- Impact Analysis
- Architecture Validation
```

This file contains repository facts only.

No workflow instructions.

No AI-specific content.

---

## AGENT.md

Location:

```text
.lea/AGENT.md
```

Purpose:

Define the recommended structural reasoning workflow for agents.

Example:

```markdown
# Structural Reasoning Protocol

This repository contains a deterministic structural graph generated by Lea.

Before inspecting source files:

1. Discover the relevant symbol.
2. Inspect structural dependencies.
3. Analyze execution paths.
4. Retrieve minimal context.
5. Apply modifications.
6. Validate architecture constraints.

Avoid:

- Full repository scans.
- Recursive grep exploration.
- Reading unrelated files.

Prefer structural navigation whenever possible.
```

This file defines reasoning behavior rather than repository facts.

```bash
lea export claude
```

```text
CLAUDE.md
```

# Relationship With Lynx

Lea and Lynx serve different responsibilities.

## Lynx

Purpose:

Natural language discovery.

Responsibilities:

* Semantic search
* Lexical search
* Natural language understanding
* Query-to-symbol resolution

Example:

```text
"How is MFA implemented?"
```

↓

```text
func:internal/auth/session:CreateMFASession
```

---

## Lea

Purpose:

Structural reasoning.

Responsibilities:

* Graph traversal
* Call graph analysis
* Dependency analysis
* Impact analysis
* Architecture validation
* Context compilation

Example:

```text
func:internal/auth/session:CreateMFASession
```

↓

```text
Execution path
Dependencies
Callers
Architecture layer
Blast radius
```

# Guiding Principle

Lea is not a code search engine.

Lea is not a vector database.

Lea is not a prompt generator.

Lea is the structural source of truth for software systems.

Its responsibility is to transform source code into a deterministic graph that both humans and AI agents can reason about with confidence.
